# 反思

## 哪一個節點最常出錯？
**Ingest（把來源轉成 Wiki 頁面）**。這次的錯誤都出在「內容轉換」的地方：
- 摘要末尾差點放進一則並非逐字原文的引用（事後自我複查才發現）。
- 簡報與 Wiki 用詞不一致（何時 vs 什麼時候），是產生簡報時才暴露。
- 我自己整理的概念化流程，差點被當成來源明列的內容。

共同點：**LLM 會把「看起來合理的內容」混進「有來源的內容」**，而且不加標記。

## 我把檢查往前移到哪裡？
- **引用規則前移到 ingest 階段**：不等簡報完成，每寫完一個來源頁就檢查（url、引用數量與長度），並在 `CLAUDE.md` 規定「引用只能取自實際擷取到的文字」。
- **簡報的接地檢查前移到「產生時」**：每張投影片必須先宣告 `data-wiki` 與 `data-terms`，要用的術語在寫的當下就要對得上 Wiki，而不是做完才找問題。

## 有沒有修改 workflow / graph？為什麼？
有。修改前的想法是「產出簡報 → 最後統一檢查」；修改後變成**三個檢查點**：
1. ingest 後（檢查 A）
2. 簡報產生後（檢查 B）
3. 人工複查（腳本看不到的語意與概念化內容）

原因：只在最後檢查，錯誤發現得晚，修改範圍大；而且腳本只能抓到「詞沒出現」，抓不到「語意不準」，所以必須保留人工節點，不能全靠自動化。

## 限制（誠實說明）
- 檢查腳本是**字串層級**的接地檢查，不是事實查核。
- 這次只實際跑了一輪，反思是依這一輪的紀錄寫的，不代表所有情況。
