什麼是 AI Agent？

能代替你獨立完成任務的系統。

  • 用 LLM（大型語言模型）管理流程、做決策
  • 知道任務何時完成，必要時自我修正
  • 失敗時把控制權交還給使用者

白話：聊天機器人是「你問、它答」；Agent 是「你交代目標，它自己想辦法做完」。

Agent 的零件（一）：大腦＋三個組件

規劃 Planning

把大目標拆成子目標；回顧做過的事並改進。

記憶 Memory

短期：放在 context 內，容量有限。長期：外部向量資料庫，需要時檢索。

工具使用 Tool use

呼叫外部 API，取得模型本身沒有的資訊或能力。

中心是 LLM，扮演「控制器」。

Agent 的零件（二）：實作時看這三樣

模型

負責推理與決策。

工具

資料工具、行動工具、編排工具。

指示

清楚的逐步指引，連邊界情況也寫進去。

Anthropic 的基本單元叫 Augmented LLM：LLM ＋ 檢索 ＋ 工具 ＋ 記憶。

什麼時候停？

  • 沒有更多工具呼叫
  • 產出了最終結果
  • 發生錯誤
  • 達到回合上限

ReAct：邊想邊做

想（推理）→ 做（行動）→ 看結果→ 再想…
  • 只想不做（chain-of-thought）：沒接地到外部世界，容易幻覺
  • 只做不想：缺少目標與進度追蹤
  • 交錯進行：推理規劃、行動取得真實資訊

工具與 MCP

資料工具

取得資訊：資料庫查詢、網頁搜尋。

行動工具

改變系統：寄信、更新紀錄。

編排工具

把另一個 agent 當工具呼叫。

MCP：開源標準，讓 AI 應用（MCP client）用同一種方式連接資料來源（MCP server），不用每個來源都客製整合。

風險：Agent 會在哪裡出錯？

  • Context 長度有限：記不住太多
  • 長期規劃困難：遇到意外不易調整計畫
  • 介面脆弱：輸出格式可能出錯
  • 錯誤累積、成本較高

對策：多層護欄（分類器、個資過濾、規則檢查、輸出驗證）＋ 高風險、不可逆動作交給人類介入。

什麼時候該用 Agent？

先問：最簡單的方案夠不夠？

  1. 單次 LLM 呼叫能解決 → 用它
  2. 步驟固定、可預先寫好 → workflow
  3. 步驟無法預測、需要判斷 → agent ＋ 護欄

適合 agent 的跡象：複雜判斷或例外多、規則集龐大難維護、依賴非結構化資料。

小測驗（點開看答案）

Q1. 「每天固定把表單資料寄給主管」比較像 workflow 還是 agent？

Workflow：步驟固定、可預先寫好。

Q2. Agent 什麼時候應該停下來？

沒有更多工具呼叫、產出最終結果、發生錯誤或達到回合上限。

Q3. 要執行大額付款這種動作，Agent 應該怎麼做？

交給人類介入，因為是高風險、不可逆的動作。
